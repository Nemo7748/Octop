# 接口与数据库约定

> **适用对象**：本仓库全部业务开发（B 制作区、C 前端、D 数据库与权限、E 测试）。
> **与既有文档的关系**：端点清单见 [`docs/api.md`](../api.md)；模块边界、测试门槛见 [`AGENTS.md`](../../AGENTS.md)；本文只回答一个问题——**怎么改才不算破坏公共契约**。
> **维护人**：A（总负责人 / 仓库管理员）。改本文要走 PR。

---

## 0. 一条原则

接口和表结构是五个人的公共契约。**改之前先通知，改的时候同步文档，改完自己跑通。**
没有通知的接口改动，审核一律驳回，不讨论。

## 1. HTTP 接口约定

### 1.1 路由与命名

- 所有路由挂在 `/api` 下，挂载表在 [`src/octop/api/app.py:144`](../../src/octop/api/app.py)。
- 资源用复数：`/api/agents`、`/api/users`；子资源用层级：`/api/agents/{agent_id}/files`。
- 对外标识用字符串业务键（`agent_id`、`thread_id`、`session_key`），**不要把自增 `id` 放进 URL**。数据库里 `id` 是内部主键，`agent_id` 才是对外身份（见 `001_initial.sql` 的 `agents` 表）。
- 新路由必须：登记进 `app.py` 挂载表 → 给 `tags` → 在 `api/openapi_meta.py` 写 tag 描述 → 每个路由给 `summary`。
- 路由函数保持"薄"：只做 HTTP 校验、调 `infra/`、映射错误。业务规则写在 `infra/`，不要写进 router。

### 1.2 认证与鉴权

| 级别 | 含义 |
|---|---|
| public | 无需 token（`/api/auth/login`、`/api/health`、setup 引导） |
| user | 任意登录用户 |
| owner | 资源所有者，或管理员 |
| admin | 仅管理员 |

- 认证头：`Authorization: Bearer <access_token>`，token 由 `POST /api/auth/login` 签发，TTL 见 `OCTOP_ACCESS_TOKEN_TTL`（默认 24h）。
- 鉴权失败**必须抛 `OctopError`**，不要 `raise HTTPException(403, "…")`：后者绕过错误码机制，前端 `apiErrors.*` 会对不上，联调时会变成"页面只显示 403 没有提示"。

### 1.3 错误信封（所有非 2xx）

```json
{ "error": { "code": "AGENT_NOT_FOUND", "message": "…", "details": {} } }
```

- `code` **必须**取自 [`src/octop/infra/errors.py`](../../src/octop/infra/errors.py) 的 `ErrorCode`。
- 新增一个 code 要同时做三件事：`ErrorCode` 加枚举 → `src/octop/i18n/{en,zh}.json` 的 `errors.<CODE>` 加文案 → `dashboard/src/locales/{en,zh}.json` 的 `apiErrors.*` 加文案。三处缺一处，`tests/unit/i18n` 会红。
- 禁止自定义裸字符串错误码（`"AGENT_GONE"` 这种临时拼的）。

### 1.4 分页

**现状**：全项目只有两处用到 `limit`（[`memory.py:446`](../../src/octop/api/routers/memory.py) 与 `:550`），没有 `offset` / `cursor` / `page` 的约定，也没有任何列表接口做分页。

**本次新立的规矩（仅约束新接口，存量不动）**：

- 入参：`limit`（默认 20，`ge=1, le=100`）、`cursor`（可选、不透明字符串）。
- 出参：`{ "items": [ … ], "next_cursor": "…" }`，`next_cursor` 为 `null` 表示没有下一页。
- 不用 `page/page_size`，也不返回 `total`（SQLite 上 `COUNT(*)` 是额外全表扫描，列表页不需要）。

> 这条约定尚未在任何接口上落地。第一个用它的接口负责写进 `docs/api.md` 当范例。

### 1.5 时间、金额、布尔

- 时间一律 `INTEGER` 毫秒时间戳，字段名 `*_at`。不要字符串时间，不要秒级。
- 金额用整数分，不要 float。
- SQLite 没有布尔类型，用 `INTEGER 0/1`（现状即如此，如 `agents.enabled`）。

### 1.6 流式与实时

- 聊天主通道是 **WebSocket**（见 `docs/api.md` 的 "Chat (WebSocket)"）。
- **SSE 实际用得比想象中多**：备份导出（`routers/backup.py`）、工作区文件读取（`workspace.py`）、语音（`voice.py`）、memory 导出（`memory_portable.py`）、内部 MCP（`internal_mcp.py`）都在返回 `StreamingResponse`。新增流式接口沿用同一套写法，并在 `docs/api.md` 标注。
- 新增耗时操作优先"提交任务 + 轮询状态"或 SSE，不要在普通 HTTP 请求里同步跑几十秒——网关和浏览器都会先超时。

## 2. 契约变更流程（"谁改接口必须群里说"的落地形式）

### 2.1 什么算契约变更

满足任意一条即算：

- URL 路径、HTTP 方法变化；
- 请求/响应字段**增删改名**，或类型、可空性、取值范围变化；
- 状态码、错误 `code` 变化；
- 默认值、分页方式变化；
- 表结构变化（见第 3 节）。

只是内部实现重构、返回内容完全等价，不算契约变更。

### 2.2 必须做的四步

1. **群里通知**（模板见 2.3），@ 到受影响的人。
2. **PR 标题加 `[contract]` 前缀**，GitHub 标签加 `contract-change`。
3. **同一个 PR 内**更新 `docs/api.md`，以及前端 `apiErrors.*`（若涉及错误码）。
4. **A 审核时确认调用方已知悉**；调用方未确认，PR 不合。

### 2.3 通知模板（复制粘贴用）

```
【接口变更】<接口名>
影响方：<前端 C / 数据库 D / 测试 E / 全部>
变更前：<METHOD /path，字段 a,b,c>
变更后：<METHOD /path，字段 a,b,c'，新增 d>
兼容性：破坏性 / 向后兼容
PR：#<编号>
生效：<合并后立即 / 随下个版本发布>
```

## 3. 数据库约定

### 3.1 引擎与访问边界

- SQLite + `aiosqlite`，WAL 模式；库文件 `~/.octop/octop.db`，Docker 内为 `/data/.octop/octop.db`。
- **SQL 只允许出现在** [`src/octop/infra/db/repos/`](../../src/octop/infra/db/repos/) 下，一表一个 repo（现有 16 个 repo 文件对应 18 张表；`_schema_version` 与 `connector_oauth_states` 没有独立 repo）。
- router、CLI、前端适配层**一律不准直接写 SQL**；要用数据就经 `server.services` / `RepoBundle`（[`src/octop/infra/db/services.py`](../../src/octop/infra/db/services.py)）拿 repo。
- `infra/db/repos/` 不许反向依赖 `agents/`、`gateway/` 等上层包。

### 3.2 迁移规则

- 路径：[`src/octop/infra/db/migrations/`](../../src/octop/infra/db/migrations/)，命名 `00N_简短描述.sql`。**当前只有 `001_initial.sql`**，所以下一个迁移是 `002_*.sql`。
- **禁止修改已合并的迁移文件**。哪怕只改一个空格，别人的本地库和 CI 会分叉。
- 每个新迁移要同步提升 `_schema_version` 的断言：`tests/unit/db/test_db_pool.py` 里的 `v == 1` 改成新值。
- 新列尽量可空或带默认值；SQLite 删列/改类型要重建表，属于破坏性变更，必须先单独评估并给回滚方案。

### 3.3 表结构细则

| 项目 | 约定 |
|---|---|
| 表名 | 小写、复数（`agents`、`cron_jobs`） |
| 列名 | snake_case |
| 主键 | `id INTEGER PRIMARY KEY AUTOINCREMENT` |
| 业务标识 | 单独一列且 `UNIQUE`（`agent_id`、`thread_id`、`session_key`） |
| 时间列 | `INTEGER` 毫秒，命名 `*_at` |
| JSON 列 | 列名以 `_json` 结尾（`config_json`、`extra_json`），读写显式序列化 |
| 外键 | `REFERENCES … ON DELETE CASCADE`，删除级联影响写进 PR 说明 |
| 索引 | `idx_<表>_<列>`，多列用下划线连接 |
| 审计 | 涉及用户数据读写的接口落 `audit_log`（[`infra/db/repos/audit.py`](../../src/octop/infra/db/repos/audit.py)） |

### 3.4 现有 18 张表（来自 `001_initial.sql`）

`users`、`agents`、`providers`、`voice_providers`、`sessions`、`threads`、`channels`、`cron_jobs`、`connectors`、`connector_oauth_states`、`secrets`、`settings`、`storage_backends`、`audit_log`、`usage_log`、`proactive_care_config`、`care_push_records`、`_schema_version`。

两张核心表的现状，改之前务必先看：

- `agents`：`agent_id TEXT UNIQUE`、`user_id`（所有者）、`name`、`enabled`、`config_json`；`UNIQUE(user_id, name)` 保证同一用户下重名。
- `sessions` / `threads`：都以 `(agent_id, user_id)` 为维度，这是"智能体按用户隔离"的根源（见 [底座改造方案](03-底座改造方案.md)）。

### 3.5 数据变更流程

1. 表结构变更同样**算契约变更**，走第 2 节的通知流程。
2. 需要回填历史的，迁移后附 `scripts/` 下一次性脚本，并在 PR 里写清**幂等性**（重复执行是否安全）。
3. PR 描述必须写回滚方案：这个迁移撤回时要执行什么。

## 4. 前端与接口的边界

- 前端只经 `/api` HTTP 访问后端，**不得** import Python 结构、不得假设后端目录布局。
- 请求封装放 `dashboard/src/api/modules/*`，页面里不要直接 `fetch`。
- 错误码镜像：`dashboard/src/locales/{en,zh}.json` 的 `apiErrors.*` 必须与后端 `ErrorCode` 对齐（有测试校验）。
- 界面文案走 i18next（`dashboard/src/locales/`），不写死中文或英文。

## 5. 提交前自检（每个人 PR 之前跑一遍）

```bash
uv run pytest -m "not live"     # 单元 + 集成（不调真实 LLM）
make lint                       # ruff check + format check
make typecheck                  # mypy --strict src/octop
cd dashboard && npx tsc --noEmit  # 只要动了前端就跑
```

后端改动没跑通 `make all`（lint + typecheck + test），PR 不进入审核队列。
